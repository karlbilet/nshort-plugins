# 红果 JS 插件 1.1.0

N果「设置 → JS 源插件」导入 `hongguo-1080.js`，手动启用后点击「浏览」。普通账号只要已获红果源权限即可使用；剧集保持独立插件身份，账号与同步继续由 N果管理。

**需要包含本轮 CENC 插件契约的新 App 构建。** 旧 App 仅支持 URL/quality，更新 JS 无法补齐宿主的密钥传递。当前按用户要求只做本地提交，没有更新 GitHub URL 或 TestFlight。

## 1.1.0 更新

- 参考内置红果，先请求普通 `/novel/player/multi_video_model/v1/`，无可用候选再试 preload，最后使用受限网页公开回退。每次仅提交当前分集的一个 ID，不批量请求整剧。
- 高清参数放在 `biz_param`，包括 `need_all_video_definition:true`、`video_platform:1024`；播放请求补齐设备/播放器查询参数及签名。
- 使用与内置 `hongguoContentKey` / Swift `ContentKey.decode` 一致的算法解析 `spade_a`，以合成向量验证。选择最高可用分辨率，同档优先 H.264；跳过 bytevc2 和无效密钥，不再跳过全部加密档位。
- 支持 Base64 媒体地址、同档备用地址及较低档候选，每个 URL 独立携带对应的 CENC 密钥。
- 声明官方模型实际返回的 `v3-reading-videocdn302.qznovelvod.com`，保留 `p3-reading-sign.fqnovelpic.com` 海报主机；详情页也返回海报。

## 契约与播放

旧的 `{url, quality}` 明文插件继续可用。加密候选增加 `cencKey`：**恰好 32 个十六进制字符的 AES-128 内容密钥**；未加密候选不传此字段，不传空字符串。`variants` 是最多 16 个同结构、不可嵌套的备选，密钥不能在候选之间共用或继承。

App 校验精确主机和密钥格式，再交给现有的播放/解密流程。Flutter 五端使用既有原生播放器解密选项，原生 tvOS 使用既有 `MediaDescriptor`、本机媒体准备及 Bento4。脚本不处理媒体二进制，不保存内容密钥，不接收账号凭证，也不能设置任意请求头、文件路径或播放会话。

目录、搜索和详情保留既有路径；App 仍对插件海报使用 HEIC 兼容转换。未声明图片只显示占位，未声明视频被拒绝。根域的可信分类不等于子域通配；服务端增加 CDN 时需核实后更新精确清单。

## 画质与限制

1080p 取决于源站实际返回的可用候选，不伪造清晰度。App 候选全部不可用才回退同集网页，网页回退可能只有 360p；继续检查剧集/分集身份和免费试看范围。未知密钥版本和不支持的编码不会交给播放器尝试。

目录仍只取分类首页，未实现翻页游标。搜索依赖网页结构；弹幕和多季方法仍是空结果。画中画继续受宿主现有加密媒体支持范围限制，本次不新增加密 PiP 能力。

## 验证

```sh
node --test hongguo/hongguo-1080.test.mjs
```

Node 用例使用合成响应，不访问真实源站或图片；插件运行代码没有 Node 模块依赖。覆盖内置合成密钥向量、Base64 URL、加密 1080p 优先、候选配对、无效密钥、未声明主机、错误分集、旧明文行为及网页回退。

NShortApp 仓库另有 Go QuickJS、Go/Swift 契约和播放桥回归，以及普通账号 iOS 模拟器的海报、同步与实际分辨率验收。记录：`docs/acceptance/js-plugin-cenc-2026-10-22.md`。单元测试或 tvOS 编译不替代其他平台/真机验收。
