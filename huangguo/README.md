# 黄果内置解析插件 1.0.0

两个独立入口：

- [黄果视频](huangguo-video.js)：需要账号拥有 `huangguo-video` 权限。
- [黄果 AI](huangguo-ai.js)：需要账号拥有 `huangguoai` 权限。

普通账号可以使用。导入后手动启用，在独立「插件」页或设置中的「浏览」进入；收藏、观看进度与账号同步继续由 N果管理，插件身份与内置源分开保存。

**需要包含 `builtinSource` 契约的配套 N果 App。该 App 改动目前仅在本地提交，尚未发布。** 旧 App 无法启用此绑定；仅导入或更新 JS 不能补齐宿主能力。

配套 App 中可在「设置 → JS 源插件 → 从 URL 导入」使用以下地址，保存后手动启用：

| 插件 | 导入地址 |
| --- | --- |
| 黄果视频 | `https://raw.githubusercontent.com/karlbilet/nshort-plugins/main/huangguo/huangguo-video.js` |
| 黄果 AI | `https://raw.githubusercontent.com/karlbilet/nshort-plugins/main/huangguo/huangguo-ai.js` |

也可以从本地文件或粘贴脚本导入。普通账号需要拥有对应源权限。

## 工作方式

清单绑定一个宿主内置源，`hosts` 为空。JS 通过既有 `nshort.catalog/search/detail/play` 返回有限的请求描述，App 验证后调用已有黄果目录、详情、浏览器会话和媒体解析；不在 JS 中重复维护网络指纹、播放凭证或解密器。脚本不能发起网络请求、指定任意 URL、添加请求头或切换源权限。

这是复用 N果现有解析的独立插件，不是 REX 模块的解密版。入口/参数可随插件更新，取流解析修复仍依赖配套 App 更新。

## 画质和搜索

自动播放优先请求 1080p；实际存在多个 HLS 档位时，由内置播放器选择可用档位。仅有 720p 或单一地址时保持源站真实画质，不把它标为 1080p，不做升频或转码。用户明确选择的其他档位继续传给播放器。

搜索复用内置黄果行为：检索当前已加载的目录。需要查找更多内容时，先在插件目录加载更多，再搜索；并非全站搜索服务。暂不增加黄果弹幕和多季接口。

黄果视频使用其现有浏览器和播放会话处理。黄果 AI 的海报可来自内置响应中的实际图片 CDN；宿主仅下载内置目录/详情返回的海报，更新或重启后重新校验，不开放脚本的任意图片域名访问。

## 本地验证

```sh
node --test huangguo/huangguo.test.mjs
```

Node 使用合成输入，验证绑定、请求字段、缺少编号、默认 1080p 与明确档位。配套 App 的 Go/Swift 测试覆盖实际 QuickJS、权限隔离、海报恢复和 HLS 档位；iOS 模拟器验收单独记录真实海报、搜索、同步与解码尺寸，不能以清晰度标签代替实际播放证明。
